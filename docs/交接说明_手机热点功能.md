# 交接说明：手机热点（APP 控制）功能

> 最后更新：2026-09-04

## 一、功能概述

在相机系统设置中新增了 **"手机APP连接"（热点）** 页面。用户进入该页面后，可以打开相机自身发射的 WiFi 热点（AP 模式），手机连接该热点后，可通过专门的 APP 下发协议命令，实现下载图片/视频、远程拍照录像、以及其他参数设置等功能。

**当前完成度**：UI 页面、热点开启/关闭、JL25 APP 协议、相册浏览、媒体下载和 `dc309` 本地 RTSP 预览流均已完成并完成板端联调。

## 三、关键技术点与踩坑记录（重要！）

### 1. 热点开启的核心链路

UI 层不通过消息状态机（`MODEMNG_SendMessage`），而是**直接调用底层 hal 库接口**：

```
page_sysmenu_hotspot.c
  └─ hotspot_set_enabled(enable)
       └─ WIFI_AP_Start("wlan0", &apCfg)   /   WIFI_AP_Stop()
```

热点页面仍直接调用底层 AP 接口，不依赖工作模式消息；这样可以在 `WORK_MODE_BOOT` 下稳定开启热点。APP 的预览、拍照和录像命令则由 `dc309` 协议层负责自动切换到所需工作模式。

### 2. 三个必须踩的坑（已解决）

**坑 1：不能走 `WIFIMNG_Start`（会重新 insmod 驱动失败）**
- `WIFIMNG_Start` → `HAL_WIFI_Init` → `WIFI_HAL_LoadAPDriver()` 会 `insmod 8189fs.ko`。
- 但驱动已被 wifi-daemon 加载（STA 模式），再次 insmod 报 `errno 17 (EEXIST)`，`HAL_WIFI_Init` 失败。
- **解决**：直接调用 `WIFI_AP_Start`（绕过驱动加载，利用已加载驱动）。

**坑 2：hostapd 显示 AP-ENABLED 但手机搜不到 —— 必须重新加载驱动**
- 驱动被 wpa_supplicant（STA）用过后，直接启动 hostapd，驱动不会干净切换 AP 模式，beacon 不发。
- **解决**：在 `WIFI_AP_Start` 中，先 `rmmod 8189fs` 再 `insmod /system/ko/3rd/8189fs.ko`，让驱动从干净 AP 状态启动。
- 手动测试验证：重载驱动后手机能搜到并连接（`AP-STA-CONNECTED`）。

**坑 3：wpa_supplicant / wifi-daemon / dhcpcd 会干扰 AP**
- 这些进程会把 wlan0 当 STA 连路由器，与 hostapd 冲突（dmesg 反复出现 `rtw_set_802_11_connect`）。
- **解决**：`WIFI_AP_Start` 中先 `killall wpa_supplicant wifi-daemon dhcpcd aicam_wifi`；`WIFI_AP_Stop` 中恢复 wpa_supplicant + wifi-daemon + dhcpcd。

### 3. hostapd 配置要点

`WIFI_HAL_UpdateApConfig`（rtl8189fs/wifi_hal.c）生成 hostapd.conf：
- **`wpa=2`**（不能用 `wpa=3`，否则 RTL8189FS 驱动报 `key not allowed`）。
- **`rsn_pairwise=CCMP`** + **`wpa_pairwise=CCMP`**（WPA2 标准配置）。
- **`ieee80211n=0`**（关闭 HT，纯 802.11g，更稳定；`ieee80211n=1` 时日志显示 `ht_enabled=1` 可能导致兼容问题）。
- 去掉 `ieee80211n=1` 和 `wpa=3` 是必须的，否则驱动报错或 beacon 不稳定。

### 4. udhcpd（DHCP）配置

`/etc/network/udhcpd.conf`（在 `install/soc_cv1842cp_dc309_spinand/rootfs/etc/network/`）：
- 热点 AP 的 IP 是 `192.168.169.1`（`HAL_WIFI_IP`）。
- udhcpd 地址池必须改为 `192.168.169.10 - 192.168.169.254`，网关 `192.168.169.1`，否则手机连上拿不到 IP、访问不了相机。
- 注意：这是 SDK 构建产物路径，如果重新打包 rootfs 可能被覆盖，需确认源文件位置。

### 5. UI 层注意事项

- **线程处理卡顿**：`WIFI_AP_Start/Stop` 内部有多次 usleep（rmmod/insmod 等待、驱动初始化），约 1~2 秒。若在 UI 主线程同步执行会卡顿。
  - 用 `pthread` + `lv_async_call` 在后台线程执行热点操作，主线程不被阻塞。
  - 点击开关先显示"正在开启/关闭热点，请稍候..."，完成后通过 `lv_async_call` 回到主线程显示"已开启/已关闭"。
- **普通 WiFi 与热点状态分离**：`PARAM_WIFI_S.Enable` 只表示 STA/普通 WiFi 开关状态，不能作为 AP 热点状态。热点页面的 `hs_switch`、状态圆点和状态文字使用 `JL25_IsRunning()` 判断，普通 WiFi 开机默认开启时热点状态仍应显示关闭。
- **APP 连接成功提示**：APP 成功建立 TCP `6035` 长连接并完成客户端线程创建后，`jl25_appsock.c` 调用连接回调；热点页面通过 `str_language_connection_successful` 和 `top_notice_show_for()` 显示“连接成功”。`top_notice_show_for()` 通过 `lv_async_call()` 回到 LVGL 线程。
- **退出页面关热点**：统一的 `hotspot_exit_page()`，在返回按钮、右滑、菜单键三种退出方式中调用，退出前若热点开启则先关闭，恢复正常联网模式。
- **`get_usr_fonts` 单例字体**：内部用全局单例 `font_chs`，同一页面多次调用不同大小会覆盖，本页面统一复用同一个字体指针（`hs_font`），小字用静态字体 `lv_font_SourceHanSerifSC_Regular_16`。

### 6. 编译相关坑

- `hal_wifi_common.h` 不在 UI 工程的 include 路径中（在 hal 库源目录），UI 层不能直接 `#include`。
  - **解决**：UI 层用 `extern` 声明 `WIFI_AP_Start`/`WIFI_AP_Stop`。
- 函数定义顺序：`hotspot_exit_page` 调用 `hotspot_set_enabled`，需在文件前部加前置声明，否则 `-Werror=implicit-function-declaration` 报错。
- `-Werror` 开启：`const` 指针赋值需强转（如 `hs_font = (lv_font_t *)&lv_font_SourceHanSerifSC_Regular_20;`）。

### 2. 架构决策（为什么不用 thttpd/netctrl）

- 设备 defconfig（`cv1842cp_dc309_defconfig`）**未开启 `CONFIG_APPLICATION_NET`**，thttpd/netctrl 根本没运行。
- thttpd 的 URL 模式匹配写死（`app`/`cgi-bin`/`thumb/` 等，见 `oss/thttpd/config.h`），无法路由 `/Misc?` 这类 JL25xx URL。
- 因此协议模块**自包含**：自带 socket 监听（HTTP:80 + TCP:8222），不依赖 thttpd/netctrl，不改动共享代码。

### 3. 生命周期

协议服务**随热点启停**（`page_sysmenu_hotspot.c` 的 `hotspot_set_enabled`）：

```
开热点：WIFI_AP_Start 成功 → JL25_Start()（HTTP:80 + TCP:8222 监听，订阅事件）
关热点：JL25_Stop()（先停服务）→ WIFI_AP_Stop()
```

### 4. fid 映射（APP 与设备文件系统的桥梁）

fid 即设备真实文件名（与相册 page_album.c / FILEMNG 命名一致，`DSCF%05d` 格式）：
- 照片：`/mnt/sd/DCIM/PHOTO/DSCF00001.jpg` → fid `DSCF00001.jpg`
- 视频：`/mnt/sd/DCIM/MOVIE/DSCF00002.mov` → fid `DSCF00002.mov`
- 查找规则：按扩展名定位目录（.jpg→PHOTO，.mov→MOVIE），未知扩展名先 PHOTO 后 MOVIE 探测。
- 缩略图优先返回已提取的 `/mnt/sd/.thumb/PHOTO_SMALL|MOVIE_SMALL/<同名>.jpg`，无则回退原图。

### 5. 关键实现限制（APP 联调时注意）

1. **工作模式由协议层自动处理**：设备开机默认处于 `WORK_MODE_BOOT`。APP 发起预览、录像或拍照时，`dc309` 协议层会自动切换到 `WORK_MODE_MOVIE` 或 `WORK_MODE_PHOTO`，并等待模式切换完成后再执行操作。APP 不需要先手动切换设备页面。
2. **拍照使用照片模式路径**：由于 `dc309` 未启用 `CONFIG_ENABLE_SNAP`，拍照前会停止本地 RTSP，切到 `WORK_MODE_PHOTO`，发送拍照事件并等待照片文件生成，然后切回录像模式并恢复预览。
3. **/SetMode?Storage 回失败**：USB 存储模式需整机配合，APP 场景不用。
4. **MJPG 预览流（8221 端口）未实现**：`/Setup?GetPreviewFrame`、`/mjpglive` 当前仍未接入。APP 实际使用 `rtsp://192.168.169.1:554/liveRTSP/av4`。
5. **Pin 校验（/Pin?）未实现**：设备无密码保护需求。
6. **APP 设置项已收敛**：APP 设置页面保留 SD 卡格式化和录像/拍照分辨率；恢复出厂通过 `/app/reset` 正式执行。ESSID、WifiKey 不向 APP 暴露，相关 WiFi 设置请求直接拒绝。时间同步接口仍保留，但不作为设置页面菜单项。
7. **APP 恢复出厂不重建媒体**：`/app/reset`、`/Setup?Reset` 和旧版 `FactoryReset` 统一调用协议层 `jl25_factory_reset()`，加载默认参数并保存，保留 `FocusPos/FocusPosLock`，不发送 `EVENT_MODEMNG_SETTING`，不删除参数文件，不主动重启设备。
8. **部分状态查询无对应硬件**，保持协议兼容返回：Zoom/NightMode/FocusMode/GPS/Temperature。
9. **心跳超时未启用**：协议要求 3 分钟无命令关 WiFi AP，`JL25_AliveTimeoutCheck`（jl25_misc.c）已维护时间戳但没人轮询，当前不自动关。

### 6. 旧版 APP 兼容层

部分手机 APP 不直接使用 JL25 `/Misc` 等路径，而是先访问旧版 CGI：

- `/cgi-bin/hisnet/getwifi.cgi`
- `/cgi-bin/Config.cgi?action=get&property=Net.WIFI_AP.SSID`（HTTP 404，不暴露 SSID）
- 后续可能查询 `CryptoKey`（同样返回 HTTP 404，不暴露密码）、`FWVersion`、`UUID`、`devid`、`Camera.Menu.*`、SD 卡和预览状态
- `getwifi.cgi` 和 WIFI 属性接口统一返回 HTTP 404，使 APP 将旧版 WIFI 能力判定为不存在，避免继续创建 WIFI 名称/密码菜单
- `jl25_http.c` 会对 WIFI 相关 query 脱敏，避免 SSID/密码出现在 `syslog/messages`
- `/app/setting?param=enter/exit` 是设置页导航动作，必须返回 HTTP 200 + `{"result":0,"info":"set success."}`；如果返回 `unsupported`，部分 APP 会回退到内置菜单并重新显示 WIFI 名称/密码。
- 协议服务启动时会打印 `settings_policy=sd-format-only ... wifi_probe=http-404/absent product_template=legacy-cardv policy_version=5`；关键设置接口会打印 `jl25 resp path=... http_status=...`。如果现场仍看到旧的 `policy_version=4`，说明设备运行的仍是上一个版本的 `sophcam`。
- WIFI 相关响应日志会显示 `body=[redacted]`，不会记录 SSID 或密码；`/app/capability`、`/app/getdeviceattr`、`/app/getparamitems` 等接口会记录实际响应，便于确认 APP 收到的内容。

`jl25_legacy.c` 已在同一个 HTTP:80 服务中兼容这些入口，返回旧 `netctrl` 使用的纯文本格式（`0\nOK\n` / `key=value`），不依赖 `/tmp/aicam_wifi.sock`、thttpd 或 netctrl 进程。

媒体控制接口：

```text
# JL25 标准接口
/Setup?Shutter=0    # 停止录像
/Setup?Shutter=1    # 开始录像
/Setup?Shutter=2    # 拍照

# 旧版 APP 兼容接口
/cgi-bin/Config.cgi?action=set&property=Video&value=recordon
/cgi-bin/Config.cgi?action=set&property=Video&value=recordoff
/cgi-bin/Config.cgi?action=set&property=Video&value=capture

# APP 扩展接口
/app/startrecord
/app/stoprecord
/app/takephoto
```

录像控制通过 `EVENT_MODEMNG_START_REC` / `EVENT_MODEMNG_STOP_REC` 执行，并以实际媒体状态确认结果。拍照控制通过 `EVENT_MODEMNG_START_PIV` 执行，成功条件是照片目录生成新文件。
