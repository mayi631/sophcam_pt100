# PT100 屏幕方向与 UI 布局

## 固件布局

UI 代码位于 `applications/dashcam/ui/aicamera/dc309/`。公共尺寸集中在
`src/guiguider_ui/ui_layout.h`，`include/config.h` 的 `H_RES`、`V_RES` 使用这些尺寸。

- 面板及 UI 逻辑画布均为 480×640（`UI_FB_WIDTH`、`UI_FB_HEIGHT`、`UI_WIDTH`、`UI_HEIGHT`），不交换屏幕时序参数。
- `FB_ROTATION=LV_DISPLAY_ROTATION_180` 表示面板端的最终方向，保留已确认正确的显示方向。
  之前应用逆时针 90°与内核 `tde_rot=2`（TDE 270°，实测同样为逆时针 90°）叠加，最终实际旋转了 180°。
- 应用读取 `/sys/module/cv184x_gfbg/parameters/tde_rot`，从最终角度中扣除驱动旋转角度，并据此设置 framebuffer 尺寸。
  默认 `tde_rot=2` 时，链路为 480×640 UI → LVGL 逆时针 90° → 640×480 framebuffer → TDE 逆时针 90° → 480×640 面板。
  若驱动关闭 TDE 旋转，则使用 480×640 framebuffer，由 LVGL 一次旋转 180°，最终尺寸和方向不变。
- 不能在 `tde_rot=2` 时强制 framebuffer 为 480×640，否则驱动会再次交换宽高并按旧的 640×480 边界裁剪。
  现场曾出现 framebuffer 数据完整、硬件窗口只有 480×480、硬件行跨度为 2560 字节的情况。
- MAPI 显示尺寸查询支持 `VO_OUTPUT_480x640_60`，返回 480×640、60fps，避免错误地使用零尺寸视频层。
- framebuffer 刷新回调支持 FULL 和 PARTIAL 模式的软件旋转，不能只设置旋转枚举而不旋转像素数据。
- 原 640×480 固定布局通过 `UI_X()`、`UI_Y()` 分别转换横纵坐标。
- 新增的竖屏原生坐标直接使用像素，不再套用缩放宏，避免二次缩放。
- 首页保留三行两列，入口尺寸和间距随逻辑画布缩放，避免旋转后第三行越界；顺序依次为拍照、AI 识别、相册、AI 对话、拍译、设置。按键导航同步使用两列、三行。
- 菜单、列表、状态栏、弹窗、工厂测试画布等按竖屏调整；相册保留三列，与原有导航逻辑一致。
- AI 识别和拍译结果使用上图、下文布局，中间预留重读按钮，长文本继续纵向滚动。
- 普通图片使用等比包含，首页壁纸使用等比覆盖裁剪；不将横屏图片直接拉伸为竖屏。热点二维码背景使用等比包含，避免二维码被裁掉。
- 保留原字号及原有相机、录像分辨率、JPEG 缩放参数；这些不是屏幕布局尺寸。

修改公共布局头文件后，dashcam 的 UI 对象会在下次构建时重新编译；生成的图片与字体对象不受该依赖影响。
这些修改不解决 MCU、面板或显示接口本身的故障，仍需显示驱动提供正确的 480×640 输出。
此次 UI 方向调整只需重新编译和更新正式应用，不需要修改已确认的面板 `C7=0x04`、`36=0x10` 参数。
其中 MAPI 尺寸修复需一起重新构建组件；动态链接时还需更新 `libcomp_mapi.so`，不能只替换应用可执行文件。
`components/mapi` 被应用仓库忽略，已额外保存 `docs/patches/mapi-480x640-display-size.patch`。
当前组件源码已经修复；重新导入未修复的组件时，在应用仓库根目录执行
`patch -d components/mapi -p1 --forward < docs/patches/mapi-480x640-display-size.patch` 恢复该修改。

## 拍照、录像及设置标题栏

- 拍照、录像页的交互图标使用 `ui_imagebutton_create()`：它基于可点击的普通图片，
  按控件边界等比缩放，保留原来的点击事件。原生 `lv_imagebutton` 的中间图片按原尺寸平铺，
  并在切换资源时恢复原图高度，不能通过缩小控件实现图标缩放。
- 两页按 480×640 原生坐标分配状态栏及底栏，图标为 40×40、底栏按钮为 44×44、
  SD 卡和电池为 32×32。白平衡、曝光及连拍等辅助状态与顶部主状态错行显示。
- 日期、录像时长单独放在底部按钮上方；剩余张数或录像时间使用固定宽度右对齐，避免覆盖邻近图标。
- 拍照、录像、系统设置首页去掉返回箭头旁的黄色图标，改为居中的多语言文字标题；
  返回操作和各子设置页功能保持不变。

## 本机虚拟屏预览

依赖 Python 3 和 Pillow；不需要 ADB、不编译固件，也不会操作马达或其他板端硬件。
在仓库根目录执行：

```sh
python3 applications/dashcam/ui/aicamera/dc309/scripts/preview_ui.py
```

默认输出到 `out/ui-preview/`：

- `index.html`：可点击操作的虚拟屏，含页面目录、搜索与实体键模拟。
- `home.png`：三行两列首页，使用项目原有图片和中文文本。
- `settings.png`：设置列表示意。
- `ai_result.png`：AI 结果的图片、重读、文字区域示意。
- `geometry.json`：布局区域坐标以及预览类型说明。
- `pages.json`：各模式、菜单、子菜单及控件点击区域的源码布局模型。

脚本从 C 源码和公共头文件读取布局参数，检查首页入口是否越界、重叠、数量是否匹配网格；
检查设置列表区域及 AI 结果区域的边界、重叠情况。错误时以非零状态退出。

也可以启动本机实时预览：

```sh
python3 applications/dashcam/ui/aicamera/dc309/scripts/preview_ui.py --serve
```

浏览器打开 `http://127.0.0.1:8765`；按 Ctrl-C 停止服务。
页面不再每三秒自动刷新，以免打断操作。修改 C 源码后，点击“重新读取源码”更新布局并保留当前模式；
修改 Python 服务脚本则需要重新启动服务。
可通过 `--port 8766` 改端口，或 `--output /tmp/pt100-preview` 改输出目录。
如果提示端口已被占用，先打开对应地址确认是否已有预览服务；已有服务无需重复启动。
如果端口被其他程序使用，选择空闲端口启动，不要直接结束未知进程。

### 可以操作的页面

- 首页：点击六个入口，或从左侧目录直接进入模式和子菜单。
- 拍照、录像：点击模式图标切换，点击菜单图标进入对应设置；下方实体键模拟拍照、录像开始/停止。
- 拍照与录像菜单：从源码读取当前启用的项目和选项，支持滚动、进入子菜单、模拟选择、返回及父菜单显示选项值。部分固件暂未挂入主菜单的页面仍可从左侧目录查看。
- 相册：三列缩略图，切换照片/视频、打开详情、模拟播放、选择或删除示例文件。
- AI 对话：按住说话再松开，插入离线示例消息，可检查长文本与历史滚动。
- AI 拍万物与拍译：模拟拍摄进入结果页，查看上图、重读按钮、下方长文本滚动区域。
- 系统设置：语言、WiFi、热点二维码、日期时间、音量、格式化与恢复出厂等页面；危险动作只显示浏览器确认框，不操作板端。
- 辅助操作：显示控件边框、页面搜索、返回与首页；键盘 Esc 返回、Home 首页、M 菜单、空格拍照/录像、方向键及 Enter 选择菜单项。

**该工具是源码坐标模型加浏览器交互演示，不是完整 LVGL 模拟器，也不是板端截图。**
普通菜单的列表区域、行尺寸、间隔、中文选项以及主要模式的按钮区域来自源码；
字体排版、默认样式与运行时显示/隐藏逻辑是近似实现。WiFi、日期时间、工厂测试等特殊表单和运行时 AI 选项只提供交互示意，并在页面说明中标注。
相机画面、相册文件、录音、AI 回复、播放、参数修改及网络操作均为离线示例，不执行固件 C 代码。
这不能替代所有页面的实机验收；尤其摄像画面比例、动态状态、触摸和硬件输出仍需板端验证。
