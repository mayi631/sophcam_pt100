## 三、本轮关键问题与结论

### 1. `/Storage` 完整下载与缩略图 404

此前板端出现：

- `/Storage?GetFileTHumb=...` 返回 `404`
- `/Storage?Download=...` 返回 `404`
- `/Storage?Download=...@100` 却能成功

最终结论：

- 早期失败并不是协议设计问题，而是运行中的板端二进制与源码状态不一致，叠加 HTTP 请求解析边界问题导致。
- 修正并重新部署后，`GetFileTHumb`、完整下载、断点下载均已恢复正常。
- `docs/jl25_curl_test.sh` 当前结果已经证明这部分不是“假通过”：
  - 缩略图返回 JPEG magic `ffd8`
  - 完整下载文件大小正确
  - `@100` 断点续传大小正确
  - 断点内容与完整文件尾部一致

### 2. APP 能连接但相册显示为空

APP 进入相册后，设备端实际收到的是旧 CGI 目录请求，而不是 `/app/getfilelist`：

- `/cgi-bin/Config.cgi?action=dir&property=Normal&format=all&backward=1&count=20&from=0`
- `/cgi-bin/Config.cgi?action=dir&property=Photo&format=all&backward=1&count=20&from=0`

最终结论：

- 相册为空的根因是 `jl25_legacy.c` 对 `action=dir` 的兼容不完整，APP 没有接受返回内容。
- 已补齐旧目录接口兼容后，相册列表恢复正常。

已补的兼容点：

- 支持 `Normal`、`Photo`、`Event`、`ALL` 目录请求
- 返回旧 CGI 所需 XML 结构：
  - `<Normal>` / `<Photo>` / `<Event>` / `<ALL>`
  - `<file>`
  - `<name>`
  - `<format>`
  - `<size>`
  - `<attr>`
  - `<time>`
  - `<amount>`
- `action=dir` 的行为向旧 `netctrlcgi` 靠拢：
  - 不按 `count=20` 截断
  - `<amount>` 返回总文件数
- 增加旧版 `/thumb/...` 缩略图路由，直接复用现有缩略图发送逻辑

## 六、预览流补充

预览流已补完，当前实现不再走全局 RTSP service，而是由 `dc309` 协议层本地起 `RTSP`，并把地址固定为 `rtsp://192.168.169.1:554/liveRTSP/av4`，与 APP 请求路径对齐。

本次最终对应的预览流改动文件：

- `applications/dashcam/ui/aicamera/dc309/src/protocol/jl25_preview.c`
- `applications/dashcam/ui/aicamera/dc309/src/protocol/preview_rtsp/jl25_preview_rtsp.c`
- `applications/dashcam/ui/aicamera/dc309/src/protocol/preview_rtsp/jl25_preview_rtsp.h`
- `applications/dashcam/Makefile`

协议层会在 APP 请求预览、录像或拍照时自动处理工作模式：

- 预览/录像：自动切换到 `WORK_MODE_MOVIE`，等待模式切换完成后再启动或执行录像。
- 拍照：停止本地预览，切换到 `WORK_MODE_PHOTO`，发送正常拍照事件并等待照片文件生成，再切回录像模式并恢复 RTSP 预览。
- 因此不需要用户先在设备 UI 上手动切换到拍照或录像页面。

## 九、远程拍照与录像接口

### 1. 旧版 APP 兼容接口

旧版 APP 通过 `Config.cgi` 控制媒体操作：

```text
/cgi-bin/Config.cgi?action=set&property=Video&value=recordon
/cgi-bin/Config.cgi?action=set&property=Video&value=recordoff
/cgi-bin/Config.cgi?action=set&property=Video&value=capture
```

兼容层还接受以下等价值：

- 开始录像：`recordon`、`startrecord`、`on`、`1`
- 停止录像：`recordoff`、`stoprecord`、`off`、`0`
- 拍照：`capture`、`takephoto`、`snapshot`、`2`

### 2. JL25 标准接口

```text
/Setup?Shutter=0    # 停止录像
/Setup?Shutter=1    # 开始录像
/Setup?Shutter=2    # 拍照
```

### 3. APP 扩展接口

```text
/app/startrecord
/app/stoprecord
/app/takephoto
/app/snapshot
```

### 4. 拍照特殊处理

`dc309` 未启用 `CONFIG_ENABLE_SNAP`，电影模式下不存在可用的快照线程。若直接从电影模式调用原录像服务的拍照接口，会在文件名生成流程等待，导致照片不生成且内部状态保持忙碌。

当前协议层的处理方式是：

1. 判断 SD 卡可用。
2. 停止本地 RTSP 预览。
3. 切换到 `WORK_MODE_PHOTO` 并等待完成。
4. 发送 `EVENT_MODEMNG_START_PIV`。
5. 等待 `/mnt/sd/DCIM/PHOTO` 文件数量增加。
6. 切回 `WORK_MODE_MOVIE`。
7. 若原来处于预览状态，重新启动 RTSP。
